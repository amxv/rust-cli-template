# AGENTS.md

Guidance for coding agents working in projects created from `rust-cli-template`.

## Purpose

This repository is a Rust CLI first. Release plumbing and docs already exist so product work should normally stay focused on `src/`, `tests/`, and the relevant documentation.

## Architecture

- `src/main.rs`: process boundary, error rendering, exit status.
- `src/lib.rs`: reusable application entrypoint and command dispatch.
- `src/cli.rs`: `clap` parser types and help surface.
- `src/commands/`: one module per command/domain area as the CLI grows.
- `tests/`: end-to-end binary behavior.
- `Cargo.toml`: canonical crate metadata and Rust lints.
- `dist-workspace.toml`: `dist` release/install configuration.
- `docs/`: independent Astro/ZueDocs workspace, including its own Bun lockfile and Vercel config.
- `.github/workflows/release.yml`: generated by `dist`; never hand-maintain it.

## Commands

Fast edit loop:

```bash
just check-fast
```

Full Rust validation:

```bash
just check
```

Useful scoped commands:

```bash
cargo fmt --all -- --check
cargo check --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo test --locked <test-name>
```

Validate the docs using Astro check (a local production build is unnecessary):

```bash
just docs-check
```

Release configuration:

```bash
dist plan
dist generate
```

## Coding conventions

- Use Rust 2024 idioms and the pinned toolchain in `rust-toolchain.toml`.
- Keep `main.rs` tiny. Put behavior in the library and command/domain modules so it is testable without process plumbing.
- Prefer typed `clap` arguments and subcommands over manual argument parsing.
- Preserve useful command-local `--help` output and examples as the surface grows.
- `unsafe_code` is forbidden; `dbg!`, `todo!`, and `unimplemented!` are denied by project lints.
- Keep `Cargo.lock` committed: these repos ship applications, not just libraries.

## Changing project identity

For a newly cloned template, use the bootstrap script to initialize project identity:

```bash
just bootstrap --cli-name pluck --distribution npm --npm-package @acme/pluck --description "A fast file picker"
```

For a direct install/upgrade project, use `--distribution direct` and omit
`--npm-package`. Direct mode creates website-hosted `install.sh`/`install.ps1`,
a native `upgrade --check` command, opt-in `auto-update on|off|status` for
daily background checks, and a release workflow without npm. npm
mode produces only the npm installer/publish path. The template defaults to npm.
Daily checks run via launchd (macOS), systemd user timers (Linux), or Task
Scheduler (Windows), independently of the CLI process. Auto-update is off by
default; failures do not silently turn it off or create retry loops.

Bootstrap synchronizes Cargo metadata, binary/crate references, selected
`dist` publishing method, docs identity fields, canonical URL, license, Rust
toolchain, and GitHub CI Rust version. The `just bootstrap` recipe preserves
quoted, multi-word arguments. GitHub owner/repo are inferred from the cloned origin when
possible. README and docs pages are deliberately left for project agents to
write. Once setup is final, run `just bootstrap-clean` and rerun `just check`.
Cleanup also removes the CI step that checked the now-deleted bootstrap script.

## Optional macOS menu bar scaffold

The Swift/AppKit app is opt-in via **--macos-menubar**, only with direct releases.
It lives in apps/menubar with its build script, while the Rust CLI owns
upgrade and auto-update behavior. cargo-dist includes the
.github/workflows/publish-menubar.yml custom post-announce job only for this
mode. That job attaches arm64 and Intel signed app + Rust CLI tarballs and
SHA-256 checksum sidecars to the release. The website installer installs the
pair and reopens a previously running app on upgrade.

When the flag is omitted, generate no macOS app, app CI job, or bundled
installer. Bootstrap-clean removes unused Swift templates; real app sources
are retained only in opted-in projects. Ad-hoc signing plus scripted curl/tar
installation does not provide Developer ID notarization. Do not disable
Gatekeeper or claim that browser downloads are warning-free.

## Docs boundary

Keep all web tooling in `docs/`: package metadata, Bun dependencies, Astro config, generated Astro state, and Vercel config.

The `.github/workflows/docs.yml` job is triggered by `docs/**` changes to
`main` and calls Vercel CLI for production deployments only on those pushes.
Other pushes create no Vercel deployment and use no deployment quota. Keep the
Vercel GitHub connection and Root Directory `docs`, but preserve
`git.deploymentEnabled: false` and the absence of `ignoreCommand` in
`docs/vercel.json` to avoid duplicate, quota-consuming Git deployments. Before
the first generated-project deployment, run `just vercel-provision` **after**
linking `docs/` and **before** `just bootstrap-clean`. It reuses local Vercel
CLI authentication (or a Keychain fallback) to mint a project-scoped token,
stores `VERCEL_TOKEN` as a GitHub Actions **secret**, and writes Vercel IDs as
Actions **variables**. Never print or commit credentials. GitHub Actions builds
the static Astro output and deploys it with `--prebuilt`, compatible with
restricted project tokens; local agents only run `just docs-check`. The build
runs within `docs/`, but deployment must run from repository root with the
bundle copied from `docs/.vercel/output` to `.vercel/output`, because Vercel
already has Root Directory `docs` configured. Never deploy from `docs/` with
that configuration; it resolves the project to `docs/docs`.
Run `just docs-test` to verify the GitHub filter and the retained local diff
helper (`docs/scripts/should-build.mjs`). Never re-enable automatic Vercel Git
deployments without first disabling the Actions deployment path.

## Release boundary

`dist-workspace.toml` is the source of truth for binary/install targets and
selected distribution mode. `.github/workflows/release.yml` is generated output.
If distribution changes, edit `dist-workspace.toml`, run `dist generate`, and
commit both changes together.

For any request to cut or ship a release, read and follow `.agents/skills/release/SKILL.md`.
