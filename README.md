# Rust CLI Template

A Rust-first starter for shipping command-line applications with reproducible builds, CI, GitHub Releases, and an Astro/ZueDocs website. Choose **one** distribution method during Bootstrap and retire the setup scripts when the project is initialized.

The included tooling is Rust 2024, `clap`, `anyhow`, unit/integration tests, strict Clippy, a pinned toolchain, and `cargo-dist` for native release artifacts and checksums.

| | npm | Direct |
| --- | --- | --- |
| Install | npm binary package generated by `cargo-dist` | Website-hosted shell/PowerShell installers |
| GitHub Releases | Native archives | Native archives and release installers |
| npm publication | Yes | No |
| Native `upgrade` command | No | `upgrade [--check]` |
| Optional daily auto-updates | No | `auto-update on\|off\|status` |
| `NPM_TOKEN` required | Yes | No |

The default is **npm** for backward compatibility. Direct distribution does not create an npm package or npm publishing job. Optional crates.io publishing is a separate choice.

## Create a project

Create a new GitHub repository from this template:

```bash
gh repo create acme/pluck --public --template amxv/rust-cli-template --clone
cd pluck
```

Bootstrap a CLI released through **npm**:

```bash
just bootstrap \
  --cli-name pluck \
  --distribution npm \
  --npm-package @acme/pluck \
  --description "A fast file picker" \
  --license Apache-2.0 \
  --rust-version 1.98.0
```

Or use **direct installation** with no npm publishing:

```bash
just bootstrap \
  --cli-name pluck \
  --distribution direct \
  --description "A fast file picker" \
  --homepage https://pluck.example.com \
  --canonical-url https://pluck.example.com \
  --license Apache-2.0 \
  --rust-version 1.98.0
```

`1.98.0` is the toolchain pinned in this template; for new projects, resolve the latest stable Rust and pass its exact version. The owner and repository can be inferred from `origin`. Use `--crate-name` when the Cargo crate and executable should have different names, and opt in to crates.io separately with `--crates-io` if the crate name is available. `--npm-package` is only valid in npm mode.

Bootstrap synchronizes the Cargo package and binary identity, test references, `Cargo.lock`, pinned toolchain, `dist-workspace.toml`, generated release workflow, Astro canonical URL, and site identity fields in `docs/src/data/docs.ts`. Direct bootstrap needs the `cargo-dist` version pinned in `dist-workspace.toml` so it can regenerate the release workflow.

**Bootstrap intentionally leaves `README.md` and documentation pages untouched.** The project's agent should replace starter prose with actual product guidance, update the landing page, and implement the real CLI commands. The template starts with a small `hello` command, not a finished application.

## Develop and validate

```bash
just check-fast     # Format, Cargo check, Clippy
just check          # Format, Clippy, tests
just build
just run --help
just run hello agent
```

Use `src/cli.rs` for the `clap` command model, `src/commands/` for behavior, `src/lib.rs` for dispatch, and `tests/` for integration tests. `Cargo.toml` owns the package identity and version; `Cargo.lock` stays committed.

The docs site uses Astro/ZueDocs and a separate Bun workspace:

```bash
just docs-install
just docs-dev
just docs-test
just docs-check
just docs-build
```

On Vercel, set **Root Directory `docs`**. The docs project includes an affected-path check to skip rebuilds for Rust-only changes. `docs/src/data/docs.ts` has generated identity fields; branding and actual docs content remain agent-owned.

## Direct installation and auto-updates

Direct bootstrap adds `docs/public/install.sh` and `docs/public/install.ps1` and a native `upgrade` command. The website scripts fetch the matching GitHub Release installers produced by `cargo-dist`. Once the first release and website are live, users can install with:

```bash
curl -fsSL https://pluck.example.com/install.sh | sh
```

On Windows, use the PowerShell installer at `https://pluck.example.com/install.ps1`. Direct releases include checksummed archives for Apple Silicon and Intel macOS, ARM64 and x64 Linux, and x64 Windows. `cargo-dist` generates the release's shell and PowerShell installers; it does **not** create an npm package in this mode.

The generated CLI provides:

```bash
pluck upgrade --check
pluck upgrade
pluck auto-update on
pluck auto-update status
pluck auto-update off
```

Automatic updates are **off by default** and enabled only at the user's request. Once enabled, a daily OS scheduler checks for a newer stable release, skips an already-installed version, and uses the existing release installer. This works even when the CLI is closed: macOS uses launchd, Linux uses a systemd user timer, and Windows uses Task Scheduler. The user's opt-in survives restarts and offline failures; background checks are claimed at most once per 24 hours to avoid repeated failed requests.

The canonical website must be deployed before CLI upgrades can fetch its installer. Linux needs a functioning systemd user manager, and CLIs that manage running services may require additional application-specific safety checks before performing upgrades.

## npm distribution and crates.io

npm bootstrap configures `cargo-dist` to generate the native archives and npm installer package, with a GitHub Actions npm publishing job. Before the first tag, set **`NPM_TOKEN`** in the repository's GitHub Actions secrets. The direct path has no npm package and needs no npm token.

The template disables crates.io publishing by default. If you explicitly enable `--crates-io`, check that the crate name is available and validate `cargo publish --dry-run` separately. Crates.io is independent of the GitHub/npm-or-direct choice.

## Remove Bootstrap after setup

After the crate identity, documentation URL, distribution mode, and release configuration are final:

```bash
just bootstrap-clean
just check
```

Cleanup removes `scripts/bootstrap.py`, one-time license fixtures, generated-project Bootstrap tests, temporary distribution templates, and the Bootstrap Justfile recipes. It preserves Cargo sources, normal `just` commands, `cargo-dist` settings, docs, release workflow, and all runtime code and installers required by the chosen distribution method.

## Release

`Cargo.toml` owns the version and `docs/src/content/docs/changelog.md` owns manually written release notes. Update both, run validation, commit and push, then tag the exact Cargo version:

```bash
just check
just docs-check
just docs-build
dist plan
# Edit and commit the changelog and version bump, then push main.
just release-tag 0.2.0
```

The tag triggers the generated `cargo-dist` GitHub Actions workflow. It creates the appropriate release archives and publishes to npm **only** when npm distribution was selected. Edit `dist-workspace.toml` and regenerate with `dist generate` when changing release configuration; do not hand-edit the generated release workflow.

For the full checklist, see the [release skill](.agents/skills/release/SKILL.md), `AGENTS.md`, and `CONTRIBUTORS.md`.

## Project layout

```text
Cargo.toml, Cargo.lock       Rust package and locked dependencies
rust-toolchain.toml          Pinned Rust version
src/                         CLI, command dispatch, and implementation
tests/                       Integration tests
Justfile                     Development, docs, build, and release commands
dist-workspace.toml          Selected distribution and release targets
docs/                        Astro/ZueDocs site and direct installers (if selected)
.github/workflows/           CI and generated release workflow
.agents/skills/release/      Project release procedure
```
