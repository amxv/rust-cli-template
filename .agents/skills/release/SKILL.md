# Release a Rust CLI

Use this skill when cutting a release from a project generated by `rust-cli-template`.

The repository owns version/changelog preparation. `dist` owns binary archives, installers, GitHub Release creation, attestations, and npm publication after a `v*` tag reaches GitHub.

## Preconditions

- Work from the intended release branch, normally `main`, synced with origin.
- Understand any existing uncommitted changes before editing.
- Read `Cargo.toml`, `dist-workspace.toml`, and the newest changelog entries.
- `.github/workflows/release.yml` must match `dist-workspace.toml`; if distribution config changed, run `dist generate` before release.
- `NPM_TOKEN` must exist as a GitHub Actions secret when npm publishing is enabled.

## Prepare the version

Choose the exact semver version. Update `package.version` in `Cargo.toml`, then run a Cargo command so `Cargo.lock` records the root package version.

Confirm:

```bash
cargo metadata --no-deps --format-version 1 \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["packages"][0]["version"])'
```

Do not create the tag until this value matches the requested release version.

## Changelog

Update `docs/src/content/docs/changelog.md` manually:

- newest version first
- exact version and release date
- user-visible behavior and important compatibility/installation changes
- concise summaries rather than raw commit subjects
- omit docs styling/navigation-only changes

## Validate

Run serially from the repository root:

```bash
just check
just docs-check
just docs-build
dist plan
git diff --check
```

If `dist-workspace.toml` was edited, also run `dist generate` and include the generated workflow change.

If `Cargo.toml` has `publish = true` and crates.io publication is desired, run `cargo publish --dry-run` before tagging and confirm the crate publisher setup separately. crates.io publication is optional and independent of the default npm/GitHub release path.

## Commit, push, tag

Commit the version, lockfile, changelog, and any intentional release-config changes. Push the branch first. Then:

```bash
just release-tag ${VERSION}
```

The helper refuses to tag a version that differs from Cargo metadata.

## Verify

Find and watch the generated release workflow:

```bash
gh run list --workflow release.yml --limit 5
gh run watch <run-id> --exit-status
```

Then inspect all outputs:

```bash
gh release view "v${VERSION}" --json tagName,url,assets
npm view "<npm-package>" version dist-tags.latest --json
```

Verify the expected platform archives plus shell/PowerShell/npm installer artifacts are present. If the workflow fails, inspect the failed job before retrying or changing versions.
